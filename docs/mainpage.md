Uge Game Engine {#mainpage}
===============

Uge is a Windows-only C++17 game engine built as a static library and consumed by two
client applications: **Uge-Editor** (the editor, and the startup project) and **Sandbox**.

| Area       | Technology                                        |
|------------|---------------------------------------------------|
| Rendering  | OpenGL 4.5 via GLAD + GLFW                        |
| Scenes     | EnTT entity-component-system                      |
| Scripting  | C# via an embedded Mono runtime                   |
| UI         | Dear ImGui (docking) + ImGuizmo                   |
| Assets     | assimp (meshes), stb_image (textures), YAML (data)|
| Shaders    | Runtime GLSL to SPIR-V via shaderc + SPIRV-Cross  |

@note These pages document the engine and client sources only. Everything under
`Uge/thirdparty/` is excluded from the documentation build.

Architecture at a glance
------------------------

Uge::EntryPoint defines `main`, which calls Uge::CreateApplication — implemented by the
client. The resulting Uge::Application owns the Uge::Window, an Uge::ImGuiLayer overlay
and a Uge::LayerStack. Each frame `Application::Run` computes a Uge::Timestep, updates
every layer bottom-to-top, then renders ImGui. Input events arrive from the platform
window, are wrapped as Uge::Event objects and propagate through the layer stack
top-to-bottom until one marks them handled.

    rankdir=LR;

}
@enddot

### Three separate draw paths

The renderer is not a single unified pipeline. Three paths coexist and **do not share
state** — see @ref group_renderer for details:

1. Uge::Renderer2D — batched quads, sprites, circles and MSDF text. Writes an entity ID
   per vertex so the editor can pick objects with the mouse.
2. Uge::Renderer3D — standalone textured-cube primitives.
3. Uge::Model — the real 3D mesh path, with its own shader, uniform buffers and its own
   `BeginScene`/`EndScene` pair.

### Assets are referenced by handle

Components never store asset pointers. They store an Uge::AssetHandle (a UUID), and call
sites resolve them through Uge::AssetManager::GetAsset at the point of use. See
@ref group_asset.

Building the documentation
--------------------------

Doxygen 1.14 or newer and Graphviz are required; both must be on `PATH`.

    scripts\BuildDocs.bat

Or directly:

    cd docs
    doxygen Doxyfile

Output is written to `docs/html/index.html`, and any warnings to
`docs/doxygen-warnings.log`. Both are ignored by git.

Building the engine
-------------------

Project files are generated by premake5 — the `.sln` and `.vcxproj` files are build
artifacts, so regenerate them after adding, renaming or deleting a source file.

    thirdparty\premake\bin\premake5.exe vs2022
    msbuild Uge.sln /p:Configuration=Debug /p:Platform=x64 /m

The `VULKAN_SDK` environment variable must be set, since shaderc and SPIRV-Cross are
pulled from it for runtime shader compilation. Third-party libraries are git submodules:

    git submodule update --init --recursive

Configurations are `Debug` (`UG_DEBUG`, asserts on), `Release` (`UG_RELEASE`) and
`Dist` (`UG_DIST`, verifies off).

Conventions
-----------

- Every `.cpp` under `Uge/src/` begins with `#include <ugpch.h>`.
- Uge::Ref / Uge::CreateRef wrap `std::shared_ptr`; Uge::Scope / Uge::CreateScope wrap
  `std::unique_ptr`. Prefer these over the raw STL names.
- Members are `m_camelCase`, statics are `s_camelCase`, and everything lives in
  `namespace Uge`.
- `UG_CORE_*` logging and assertion macros are for engine code; `UG_*` for client apps.
  `UG_ASSERT` compiles out outside Debug, `UG_VERIFY` survives until Dist.
- `Uge.h` is the single umbrella header for client apps; engine-internal code includes
  specific headers instead.
